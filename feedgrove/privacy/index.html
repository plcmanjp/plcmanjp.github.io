1. 요약

FeedGrove는 계정이 필요 없고 개발자가 운영하는 수집 서버가 없습니다. 앱 데이터는 기본적으로 이용자의 기기에 저장되며 개발자에게 전송되지 않습니다. 다만 이용자가 FEED/GROUP Discord 자동 전송을 명시적으로 시작하거나 저장된 다이제스트를 수동 전송하면 아래 4항의 정보가 제3자인 Discord로 전송될 수 있습니다. 현재 Play 프로덕션 버전은 vc29 0.4.2 (29)입니다. vc29에는 Google Mobile Ads Next-Gen SDK, Google User Messaging Platform(UMP) SDK와 광고 ID 권한이 포함되어 아래 4항의 데이터가 Google에 의해 처리될 수 있습니다. 그러나 vc29는 광고 표시 설정이 꺼져 있고 퍼블리셔 정책 승인도 완료되지 않아 광고 요청과 표시가 0건입니다. vc22는 광고 SDK가 없는 과거 Alpha이고 vc24는 광고 기능 검증을 위한 test-only QC 빌드입니다. SDK 포함과 광고 개시는 다른 단계입니다.

2. 개발자가 수집하는 정보

개발자는 이용자의 데이터를 개발자가 운영하는 서버로 수집하지 않습니다. 앱에는 회원가입과 로그인 기능이 없고 개발자가 운영하는 수집 서버로 데이터를 보내는 경로도 없습니다. 현재 프로덕션 vc29에는 별도의 Analytics SDK는 없지만 Google Mobile Ads Next-Gen과 UMP가 포함되며, 이 Google SDK의 처리는 개발자 자체 서버 수집과 구분됩니다.

3. 앱에 저장되는 정보

앱은 아래 정보를 기기 내부 저장소(앱 전용 데이터베이스와 설정 저장소)에 보관합니다. Discord 전송을 활성화하거나 수동 실행한 경우 일부 정보는 4항에 따라 Discord로도 전송될 수 있습니다.

  • 이용자가 등록한 피드 주소, 피드 이름, 그룹, 동기화 주기 설정
  • 수집한 게시물의 제목, 링크, 요약, 작성자, 게시 시각, 이미지 주소
  • 읽음과 즐겨찾기 표시, 검색과 목록 표시 설정
  • 이용자가 만든 파서 설정(선택자와 패턴)
  • 다이제스트 규칙과 전송 이력 상태
  • 이용자가 등록한 Discord 웹훅 주소

Discord 웹훅 주소는 Android Keystore에 보관된 기기 전용 키로 암호화(AES-256-GCM)해 저장합니다. 앱은 웹훅 주소 전체를 화면 로그나 오류 메시지에 남기지 않고 마스킹된 형태만 표시합니다.

4. 외부로 나가는 통신

앱은 다음 경로로 외부와 통신합니다.

  • 이용자가 등록한 피드 주소나 웹페이지 주소로 직접 접속해 공개된 내용을 내려받습니다. 이때 해당 사이트에는 통상적인 웹 요청 정보(IP 주소, 요청 시각, 앱 식별 문자열)가 남을 수 있으며 이는 해당 사이트 운영자의 처리 영역입니다.
  • 목록과 상세 화면에 표시할 이미지를 게시물에 포함된 이미지 주소에서 직접 내려받습니다. 이미지 호스트는 이용자가 직접 입력한 곳이 아닐 수 있습니다.
  • 이용자가 FEED 또는 GROUP Discord 대상을 만들 때는 Discord 제3자 전송, 자동 전송 필드와 실제 멘션을 검토하고 최종 시작을 별도로 확인해야 합니다. 활성과 자동 전송이 모두 켜진 대상만 다음 피드 동기화부터 조건에 맞는 항목을 백그라운드에서 전송합니다. endpoint 승인 ID 목록, template 내용 또는 대상 멘션이 바뀌면 자동 전송은 안전을 위해 꺼지고 다시 확인해야 합니다.
  • FEED/GROUP의 plain 전송에는 게시물 제목, 원문 링크, 출처명(사용자가 직접 정한 피드 표시 이름 포함)이 포함됩니다. single/multi embed 전송에는 제목, 원문 링크, 요약, 출처명, 이미지 URL, 게시 시각이 포함됩니다. 두 형식 모두 설정된 경우 Discord 멘션 대상 사용자 ID를 포함할 수 있습니다. 등록한 피드 URL 자체와 게시물 작성자는 Discord 전송 내용에 포함되지 않습니다.
  • 이용자가 저장된 다이제스트와 활성 Discord 대상을 선택해 전송하면 다이제스트 프로필 이름, 생성 시각, 포함 항목의 제목과 원문 링크, 출처명(사용자가 직접 정한 피드 표시 이름 포함), 접힘 수와, 설정된 경우 Discord 멘션 대상 사용자 ID가 포함될 수 있습니다. 게시물 요약, 이미지 URL, 게시 시각, 작성자는 다이제스트 payload에 포함되지 않습니다. 다이제스트 자동 전송은 기본적으로 꺼져 있습니다.
  • 고정 테스트 전송은 고정 문구만 Discord로 보내며 게시물, 프로필, 사용자 ID를 포함하지 않습니다.
  • 이용자가 게시물의 원문 보기나 공유를 실행하면 기기의 브라우저나 공유 대상 앱으로 제목과 링크가 전달됩니다.
  • 현재 프로덕션 vc29에 포함된 Google Mobile Ads와 UMP는 IP 주소 기반 대략적 위치, 앱 상호작용, 진단 정보, 기기 또는 기타 식별자(광고 ID(AAID), App Set ID 등)를 Google에 수집하거나 공유할 수 있습니다. 처리 목적은 광고 또는 마케팅, 분석, 부정행위 방지, 보안, 규정 준수이며 데이터는 TLS로 암호화되어 전송됩니다. vc29의 광고 요청과 표시는 현재 0건입니다.
  • 광고 기능이 활성화된 별도 빌드는 UMP를 통해 필요한 동의를 요청하고, 동의 선택을 다시 관리할 수 있는 privacy options 진입점을 제공합니다. Rewarded 광고 완료 시 비현금성 토큰 1개를 최대 5개까지 적립할 수 있고, 이용자가 별도로 확인해 토큰 1개를 사용하면 하단 배너 요청과 표시를 24시간 중단합니다. 이 광고 기능은 현재 vc29에서 비활성입니다.

앱은 이용자 기기의 연락처, 정밀 위치, 사진, 파일에 직접 접근하지 않습니다. 현재 프로덕션 vc29에는 Google Mobile Ads와 UMP, 광고 ID 권한(com.google.android.gms.permission.AD_ID)이 포함됩니다. vc22는 인터넷 접속 권한(INTERNET)만 선언한 과거 Alpha이고 vc24는 test-only QC 빌드입니다. vc29 실제 AAB의 권한은 프로덕션 제출 전에 확인했습니다.

5. 제3자 제공과 판매

개발자는 앱 데이터를 직접 받거나 판매하지 않습니다. Discord는 개발자와 별개의 제3자이며, FEED/GROUP 자동 전송을 활성화하거나 다이제스트 수동 전송을 실행하면 4항의 정보가 이용자가 등록한 Discord 웹훅으로 전달됩니다. 현재 프로덕션 vc29에 포함된 Google Mobile Ads와 UMP 처리에서는 Google이 별개의 제3자이며 4항의 광고 관련 정보를 수집하거나 공유할 수 있습니다. 피드와 이미지 호스트, Discord, Google, 브라우저와 공유 대상 앱의 데이터 처리에는 각 서비스의 정책이 적용됩니다.

6. 보관과 파기

기기 내부 데이터의 보관 기간은 이용자가 통제합니다. 앱 내에서 피드나 게시물을 삭제하면 해당 로컬 데이터가 삭제되고, 앱을 삭제하면 기기의 로컬 앱 데이터가 삭제됩니다. 다만 Android 백업 설정에 따라 일부 앱 데이터의 백업 사본이 Google 계정에 남아 재설치 때 복원될 수 있으므로, 백업 사본은 기기와 Google 계정의 백업 설정에서 관리해야 합니다. 광고 토큰 지갑과 24시간 숨김 상태는 cloud backup과 device-to-device transfer에서 제외합니다. 이미 Discord로 전송된 메시지와 첨부 정보는 앱의 로컬 데이터나 앱을 삭제해도 Discord에서 삭제되지 않습니다. 현재 프로덕션 vc29의 Google Mobile Ads와 UMP에서 Google이 처리한 데이터의 보관과 삭제는 Google의 정책과 이용자 계정과 기기 제어 수단이 적용됩니다. UMP privacy options에서 동의 선택을 변경해도 이미 처리된 데이터가 자동으로 삭제된다는 의미는 아닙니다. 개발자는 Google이 보관하는 데이터에 접근하거나 이용자를 대신해 삭제할 수 없습니다. 개발자 측 수집 서버에는 앱 데이터 사본이 없습니다.

7. 아동

이 앱은 아동을 주 대상으로 하지 않으며 아동으로부터 개인정보를 의도적으로 수집하지 않습니다.

8. 보안

웹훅 주소는 Keystore 기반 암호화로 저장합니다. Android 백업으로 앱 데이터가 복원되더라도 Keystore 키는 함께 복원되지 않을 수 있으므로, 복호화에 실패하면 전송을 중단하고 웹훅 재등록을 요구합니다. 앱은 http와 https 이외의 주소를 거부하고, 사설망이나 loopback 등 비공용 주소로의 접속을 기본 차단합니다.

9. 방침 변경

방침이 변경되면 게시 문서를 갱신하고, 앱 업데이트 설명에 변경 사실을 알립니다.

10. 저작권 등 권리 신고

앱은 이용자가 직접 등록한 RSS, Atom, 웹페이지의 공개 콘텐츠를 이용자 기기에 내려받아 보여 줍니다. 제목, 출처, 원문 링크, 제한된 요약과 원문이 제공한 이미지 주소만 다루며 원문 전체와 원문 이미지를 복제해 저장하지 않습니다.

콘텐츠 권리자께서 특정 출처의 처리에 이의가 있으시면 아래 문의처로 알려 주세요. 접수 후 7일 이내에 확인을 회신하고, 14일 이내에 조사와 조치 결정을 알려 드립니다. 조치는 해당 출처를 앱의 기본 추천 목록에서 제외하거나 광고 노출을 중단하는 방식이며, 실제 반영에는 앱 업데이트 배포 기간이 더해집니다.

앱 화면 안의 신고와 차단은 그 기기에만 적용되는 이용자 본인용 기능이며 개발자에게 전달되지 않습니다. 권리자 신고는 반드시 아래 문의처를 이용해 주세요.

1. Summary

FeedGrove requires no account, and the developer operates no collection server. App data is stored on your device by default and is not transmitted to the developer. However, if you explicitly start automatic FEED/GROUP Discord delivery or manually send a saved digest, the information described in section 4 below may be transmitted to Discord, a third party. The current Play production version is vc29 0.4.2 (29). It includes the Google Mobile Ads Next-Gen SDK, the Google User Messaging Platform (UMP) SDK, and the advertising ID permission, so Google may process the data described in section 4. However, ad display is disabled and publisher policy approval is false in vc29, so it has made zero ad requests and shown zero ads. vc22 was an earlier Alpha without the advertising SDK, and vc24 was a test-only QC build for advertising features. Including the SDK and starting ads are separate stages.

2. Information the Developer Collects

The developer does not collect your data on any server operated by the developer. The app has no sign-up or login and no path that sends data to any collection server operated by the developer. The current vc29 production build includes no separate Analytics SDK, but it does include Google Mobile Ads Next-Gen and UMP. Processing by these Google SDKs is separate from collection by a developer-operated server.

3. Information Stored by the App

The app keeps the following information in your device's internal storage (the app's private database and settings store). If you enable Discord delivery or initiate it manually, some of this information may also be transmitted to Discord as described in section 4.

  • Feed addresses, feed names, groups, and sync interval settings you register
  • Title, link, summary, author, published time, and image address of collected posts
  • Read/favorite marks and search/list display settings
  • Parser settings you create (selectors and patterns)
  • Digest rules and delivery history state
  • Discord webhook addresses you register

Discord webhook addresses are stored encrypted (AES-256-GCM) with a device-only key held in the Android Keystore. The app never writes the full webhook address to on-screen logs or error messages, showing only a masked form.

4. Outbound Communication

The app communicates externally through the following paths.

  • It connects directly to the feed or web page addresses you registered and downloads their publicly available content. In doing so, ordinary web request information (IP address, request time, app identifier string) may be recorded by that site, which falls under that site operator's processing.
  • It downloads images for the list and detail screens directly from the image addresses contained in posts. The image host may not be a destination that you entered directly.
  • When creating a FEED or GROUP Discord target, you must review the third-party transmission to Discord, the automatically transmitted fields, and the actual mentions, and then separately confirm the final start. Only a target for which both Enabled and Automatic delivery are on will transmit matching items in the background beginning with the next feed synchronization. If the endpoint's approved ID list, template content, or target mentions change, automatic delivery is turned off for safety and must be confirmed again.
  • FEED/GROUP plain delivery includes the post title, original link, and source name (including any feed display name you set yourself). Single/multi embed delivery includes the title, original link, summary, source name, image URL, and published time. Both formats may include the user IDs of Discord mention recipients if configured. The registered feed URL itself and the post author are not included in Discord delivery content.
  • If you select and send a saved digest and an active Discord target, the delivery may include the digest profile name, generation time, the title, original link, and source name (including any feed display name you set yourself) of included items, the collapsed-item count, and the user IDs of Discord mention recipients if configured. Post summaries, image URLs, published times, and authors are not included in the digest payload. Automatic digest delivery is off by default.
  • A fixed test delivery sends only fixed text to Discord and does not include posts, profiles, or user IDs.
  • When you open the original post or share it, the title and link are passed to your device's browser or the chosen share-target app.
  • Google Mobile Ads and UMP, included in the current vc29 production build, may collect and share with Google approximate location based on IP address, app interactions, diagnostics, and device or other identifiers (including Advertising ID (AAID) and App Set ID). The purposes are advertising or marketing, analytics, and fraud prevention, security, and compliance. Data is encrypted in transit using TLS. vc29 currently has zero ad requests and zero ad displays.
  • A separate build with advertising enabled uses UMP to request consent where required and provides a privacy-options entry point where you can manage your consent choices again. Completing a rewarded ad can earn one non-cash token, up to five, and if you separately confirm and spend one token, bottom banner requests and display stop for 24 hours. These advertising features are disabled in the current vc29 build.

The app does not directly access your device's contacts, precise location, photos, or files. The current vc29 production build includes Google Mobile Ads, UMP, and the advertising ID permission (com.google.android.gms.permission.AD_ID). vc22 was an earlier Alpha that declared only internet access (INTERNET), and vc24 was a test-only QC build. Permissions in the actual vc29 AAB were verified before the production submission.

5. Third-Party Sharing and Sale

The developer does not directly receive or sell app data. Discord is a third party separate from the developer. When you enable automatic FEED/GROUP delivery or initiate manual digest delivery, the information described in section 4 is transmitted to the Discord webhook you registered. For Google Mobile Ads and UMP processing in the current vc29 production build, Google is a separate third party and may collect and share the advertising-related information described in section 4. The policies of feed and image hosts, Discord, Google, browsers, and share-target apps apply to their respective processing.

6. Retention and Deletion

You control how long data is retained on your device. Deleting a feed or post in the app deletes the corresponding local data, and uninstalling the app deletes its local app data from the device. However, depending on your Android backup settings, a backup copy of some app data may remain in your Google Account and may be restored after reinstallation; manage that copy through your device and Google Account backup settings. The advertising token wallet and the 24-hour hidden state are excluded from cloud backup and device-to-device transfer. Messages and attachment information already transmitted to Discord are not deleted from Discord when you delete local app data or uninstall the app. Data processed by Google through Google Mobile Ads and UMP in the current vc29 production build is retained and deleted under Google's policies and the controls available through your account and device. Changing a consent choice through UMP privacy options does not mean data already processed is automatically deleted. The developer cannot access or delete data retained by Google on your behalf. No copy of app data exists on a collection server operated by the developer.

7. Children

This app is not primarily directed at children and does not knowingly collect personal information from children.

8. Security

Webhook addresses are stored with Keystore-based encryption. If app data is restored from an Android backup, the Keystore key may not be restored with it; if decryption fails, delivery is stopped and webhook re-registration is required. The app rejects addresses other than http and https, and blocks access to non-public addresses such as private networks and loopback by default.

9. Changes to This Policy

If this policy changes, the published document will be updated and the change will be noted in the app's update description.

10. Copyright and Other Rights Reports

The app downloads publicly available content from the RSS, Atom, and web page addresses you registered yourself and shows it on your device. It handles only the title, source, original link, a limited summary, and the image address the original provided, and it does not copy and store the full original text or the original images.

If you are a content rights holder and object to how a particular source is handled, please let us know at the contact address below. We reply with an acknowledgement within 7 days of receipt and inform you of the investigation and the action decision within 14 days. Action takes the form of removing that source from the app's default recommendation list or stopping ad display, and actual rollout adds the time needed to distribute an app update.

The report and block controls inside the app are for your own use, apply only to that device, and are not sent to the developer. For rights holder reports, please use the contact address below.
