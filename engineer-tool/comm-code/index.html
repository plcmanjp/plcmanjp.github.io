통신 코드 계산기

시리얼 통신(RS-232C, RS-485 등) 프레임 끝에 붙이는 검사값을 계산합니다. 합산, XOR, LRC 체크섬과 CRC-16(Modbus, CCITT-FALSE, XMODEM, ARC)을 지원하고, 파라미터를 직접 넣어 다른 규격에도 맞출 수 있습니다. 장비 매뉴얼의 기대 코드를 넣으면 일치 여부를 검산해 주므로 통신이 안 될 때 원인을 좁히는 데 씁니다.

대기
  • 이럴 때 씁니다: 장비에 보낼 명령 프레임의 CRC를 직접 만들 때, 받은 프레임의 검사값이 맞는지 확인할 때, 매뉴얼 예제와 내 계산이 왜 다른지 파고들 때 씁니다.
  • 쓰는 순서: 체크섬 방식이나 CRC 종류를 고르고, HEX 또는 ASCII로 바이트열을 넣은 뒤 결과의 바이트 순서(LE, BE)를 프레임 규격에 맞춰 고릅니다.
  • 자세한 사용법: 계산기 제목 행의 도움말 버튼에서 전체 설명을 볼 수 있습니다.

통신 코드 계산기 도움말

이 도구로 할 수 있는 일

  • 바이트열의 체크섬(합산 8, 합산 16, XOR 8, LRC)을 계산합니다.
  • CRC-16 4종(Modbus, CCITT-FALSE, XMODEM, ARC)을 계산합니다. 직접 입력을 고르면 Poly, Init, XorOut, RefIn, RefOut을 손으로 맞출 수 있습니다.
  • 결과를 LE(저→고)와 BE(고→저) 두 순서로 보여 줍니다.
  • 기대 코드 칸에 매뉴얼 값을 넣으면 일치하는지 검산해 줍니다.

쓰는 순서

  1. 위쪽에서 체크섬 방식 또는 CRC 종류를 고릅니다.
  2. HEX와 ASCII 중 입력 형식을 고르고 바이트열을 넣습니다. 예: 01 03 00 00 00 0A.
  3. 프레임 규격에 맞는 바이트 순서(LE, BE)를 고르고 결과를 복사합니다.
  4. 확인이 필요하면 기대 코드를 넣어 검산 결과를 봅니다.

알아두면 좋은 것

  • 체크섬, CRC는 데이터가 전송 중 깨졌는지 확인하는 검사값입니다. 암호가 아닙니다.
  • LE는 저바이트를 먼저 보내는 Modbus RTU 전송 순서이고, WORD 표시는 고→저입니다.
  • 검산값: ASCII 123456789의 CRC-16/Modbus는 WORD 4B37, LE 37 4B입니다.
  • HEX, ASCII 모두 4096 bytes까지이며, 초과분은 무시하고 경고를 표시합니다.
